Te propongo dinámicas muy concretas y probadas, diseñadas específicamente para talleres de definición del modelo Microsoft 365 (Teams + SharePoint + gobernanza). No son “juegos”: cada dinámica produce decisiones, acuerdos o inputs reutilizables para el proyecto.

Principios para que las dinámicas funcionen
Dinámicas clave por tipo de taller
Agenda ejemplo de un taller completo
Consejos de facilitación (esto marca la diferencia)

1️⃣ Principios básicos (importantísimo)
Antes de entrar en dinámicas, ten claras estas reglas:
✅ Toda dinámica debe acabar en una decisión o artefacto ✅ Tiempo limitado (relojes visibles) ✅ El consultor facilita, no decide ✅ Negocio habla primero, IT traduce después ✅ Lo que no se decide → queda explícitamente en “pendiente”
Si no, se convierten en debates eternos.

2️⃣ Dinámicas clave para los talleres
🧩 Dinámica 1 · “Mapa del trabajo real”
Objetivo: entender cómo trabajan de verdad (no cómo dicen que trabajan)
Momento: inicio del primer taller Duración: 20–30 min Participantes: área piloto + IT
Cómo funciona
En una pizarra o Miro dibujas 3 zonas:
📂 Documentos
💬 Colaboración
🔐 Permisos
Pregunta (una a una, sin debate):
¿Qué tipo de documentos usáis?
¿Cuáles cambian a menudo?
¿Con quién se comparten?
¿Qué problemas tenéis hoy?
Cada respuesta se escribe como post-it individual.
Resultado
Mapa real de necesidades.
Base para decidir Teams, bibliotecas y permisos.
Detecta contradicciones entre negocio e IT.
🧠 Clave: no corrijas nada todavía.

🧠 Dinámica 2 · “Qué NO vamos a replicar”
Objetivo: romper el reflejo de “copiar carpetas”
Momento: tras el mapa inicial Duración: 15 min Participantes: todos
Cómo funciona
Pregunta directa:“¿Qué cosas del servidor actual NO queremos repetir en Microsoft 365?”
Cada persona escribe 2–3 puntos.
Se agrupan y se votan.
Resultado
Lista oficial de anti‑patrones.
Escudo cuando más adelante alguien diga:“Hazlo como antes”.
✅ Esto da mucha autoridad al modelo nuevo.

🏗️ Dinámica 3 · “Diseña tu Team ideal”
Objetivo: definir estructura desde negocio, no desde IT
Momento: taller de diseño Duración: 30–45 min
Cómo funciona
Das una plantilla simple:
Nombre del Team
Para qué sirve
Quién entra
Qué NO debería estar aquí
Por grupos pequeños (2–3 personas):
Diseñan 1 Team del área piloto.
Cada grupo presenta su propuesta.
Resultado
Varias visiones → comparación.
Se detectan Teams:
Demasiado grandes
Demasiado pequeños
Mal enfocados
Se llega a una versión consensuada.
🎯 Esta dinámica evita Teams “cajón de sastre”.

📁 Dinámica 4 · “Carpetas vs Metadatos”
Objetivo: decidir estructura documental sin debates técnicos
Momento: diseño SharePoint Duración: 25–30 min
Cómo funciona
Pones 2 columnas:
“Necesito CLASIFICAR por…”
“Necesito AGRUPAR por…”
Negocio dice qué necesita para:
Buscar
Filtrar
Entender documentos
Tú traduces:
Clasificar → metadato
Agrupar → biblioteca / canal
Resultado
Metadatos funcionales (no teóricos).
Menos carpetas innecesarias.
SharePoint usable desde el día 1.
✅ Muy efectiva con negocio poco técnico.

🔐 Dinámica 5 · “Matriz de permisos real”
Objetivo: evitar permisos caóticos
Momento: mismo taller o siguiente Duración: 20 min
Cómo funciona
Tabla simple en pizarra:
Tipo de usuario
Qué puede ver
Qué puede editar
Ejemplos de tipos:
Todo el área
Responsables
Dirección
Externos
Solo se discute el nivel, no el “cómo”.
Resultado
Modelo de permisos claro.
Base directa para configurar Owners / Members / Visitors.
⚠️ Regla: nunca hablar de usuario a usuario, siempre por rol.

🌍 Dinámica 6 · “Semáforo del acceso externo”
Objetivo: tomar postura clara (sin miedo)
Momento: gobernanza Duración: 15 min
Cómo funciona
Presentas 3 opciones:
🟢 Permitido sin problema 🟡 Permitido con control 🔴 No permitido nunca
Y preguntas:
Compartir documentos
Invitar usuarios externos
Crear Teams
Enlaces anónimos
Se vota rápido y se justifica.
Resultado
Política de acceso externo clara.
Evita discusiones futuras con Seguridad / Legal.

✅ Dinámica 7 · “¿Esto es piloto o no?”
Objetivo: acotar alcance del piloto
Momento: cierre de Fase 0 Duración: 10–15 min
Cómo funciona
Lista de:
Contenidos
Equipos
Usuarios
Y solo dos columnas:
✅ En piloto
❌ Fuera del piloto
Resultado
Piloto bien acotado.
Evita creep de alcance.

4️⃣ Consejos de facilitación (oro puro)
✅ Lleva decisiones pre‑maquetadas, no hojas en blanco ✅ Escribe TODO visible ✅ Frena el “caso especial” ✅ Usa frases como:

“Eso lo anotamos como excepción, no como modelo” “Para el piloto, decidimos una cosa, luego ajustamos”

✅ Cierra siempre con:
Qué queda decidido
Qué queda pendiente
Cuándo se valida
